# 병합 지침: 조사 파일에 검증 결과 반영

입력: 조사 파일 groupN.md(Sonnet 조사)와 검증 파일 verify_*.md(Opus 독립 검증). 둘 다 같은 폴더에 있습니다.
목표: 검증 결과를 조사 내용에 반영한, 연구자(철학 전공)가 읽고 논문을 고를 최종본 한 파일을 만듭니다. **새로 조사하지 않습니다.** 두 파일에 있는 정보만 씁니다.

규칙
1. 키워드 섹션 형식(쉬운 설명 / 최전선 요약 / 남은 경계 / 후보 논문 표 / 팩 추천)을 유지합니다. 파일 맨 위 머리말(날짜, 담당 키워드)은 빼고 `## K<번호>.` 섹션부터 시작합니다.
2. 검증자가 "수정 필요"로 판정한 내용은 본문을 고치고, 고친 문장 끝에 `〔검증 수정〕`을 붙입니다. 검증자가 찾은 누락 논문은 후보 표에 행을 추가하고 비고에 `〔검증 추가〕`.
3. 후보 표에 `검증` 열을 추가합니다: `확인` / `수정` / `제외` / `확인 불가` / `미검증`(검증 대상이 아니었던 논문).
4. "제외 권고" 논문은 팩 추천에서 빼고, 표에는 남기되 비고에 이유를 한 줄로.
5. "남은 경계"에서 검증자가 이미 풀렸다고 한 질문은 지우지 말고 `(이미 해결: <arXiv>) 〔검증 수정〕`으로 표시합니다. 팩에 그대로 넣으면 모델이 풀린 문제를 새 문제로 낼 위험이 있기 때문입니다.
6. 대조군(#28, #30, #36, #39, #52, #66, #200, #241, #324) 겹침 판정은 검증자의 판정을 따릅니다. 팩에 넣을 때 빼야 할 절이 있으면 팩 추천에 적습니다.
7. AI가 증명·구성에 관여한 논문은 비고에 `AI 관여: <무엇을>`을 검증자 서술 기준으로 적습니다.
8. 각 키워드 섹션 끝에 `**검증 메모.**` 한 단락: 이 키워드에서 검증자가 고친 핵심과 아직 남은 불확실성.
9. 쉬운 말 유지. 수식은 그대로 두되 첫 등장 때 한 줄 풀이.

출력: 지정 파일에 Write로 저장. 마지막 응답은 파일 경로와 키워드별 최종 팩 추천 arXiv 번호만.
