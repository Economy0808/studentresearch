실험 원본은 사용자의 데스크톱 PC에 있고, 그 저장소에는 원격이 없습니다. 다른 기기에서 run.py를 실행하지 마세요. 사용자가 그 기기로 실행 위치를 옮긴다고 직접 말한 경우만 예외입니다. 데이터 폴더 하나에는 프로세스 하나만 써야 합니다.

Sonnet, Opus, Fable 세 모델이 가산 조합론 미해결 문제를 만들고, 풀고, 평가합니다. 지금 돌고 있는 프로세스는 없습니다. Fable 주간 한도가 소진되어 2026-11-07 07:00 KST 초기화까지 대기 중입니다.

다음에 할 일

11월 7일 07:03 KST에 데스크톱 세션의 일회성 예약 ca5556e1이 아래 순서를 시작합니다. Fable 평가까지 돌릴지는 사용자 결정을 기다리는 중이고, 답이 없으면 아래 순서대로 진행됩니다. 이 예약은 그 세션에 묶여 있어서, PC나 세션이 꺼져 있으면 실행되지 않습니다. 그때는 데스크톱에서 프로젝트 루트 C:\Users\user\Desktop\학자연으로 가서 직접 실행합니다. 먼저 Fable 주간 한도 초기화와 중복 run.py가 없는지 확인합니다.

python run.py --models fable solve
python run.py --models fable eval
python run.py --models sonnet,opus eval
python run.py verify

사용량 한도로 멈추면 초기화 뒤 같은 명령을 다시 실행합니다. 끝난 항목은 건너뜁니다. 그다음 순서는 다음과 같습니다.

  1. 데이터를 커밋하고 진행판을 갱신한 뒤 python analyze.py를 실행합니다.
  2. 발표 덱 수치를 갱신합니다.
  3. 사용자가 평가자를 섭외합니다. 섭외 뒤에 평가자별 풀이 배정을 설계합니다. 1인이 전부 읽으면 약 2.8만 단어라 현실적이지 않습니다.
  4. export-human을 한 번만 실행합니다. 다시 내보내면 평가자 진행이 초기화되므로 Fable 풀이가 끝난 뒤에 합니다.
  5. eval_page/index.html을 아티팩트로 게시합니다. capabilities는 {db: {}, downloads: true}이고, 주소를 README 4절에 적습니다.
  6. import-human과 최종 분석을 실행합니다. 분석 완료 목표일은 11월 21일입니다.

  • 등급 차이: 풍요로움의 Kruskal 검정은 p=0.78로 유의하지 않습니다.
  • 풀이: open 문제 성공은 0건입니다. 해결 주장 4건 가운데 체커를 통과한 2건은 같은 문제 P-d6bfbe이고, 나머지는 P-4c5a9d가 3점과 2점, P-5d88c3이 1점과 1점입니다.
  • 신규성: 유효 22문제 중 21개에서 같거나 가까운 질문이 문헌에 있었습니다. 문제당 검색 2~3회로 확인했고, 그중 15건은 변형 여부가 판단에 달려 있습니다.
  • AI 평가자: Sonnet은 문헌상 가까운 21문제 중 19개를 "알려지지 않음"이라 했고, Opus는 답한 생성 문제 15개를 전부 "알려짐"이라 했습니다. 출제 모델의 신규성 자신감은 판정과 무관하게 0.6~0.7입니다.
  • 외부 맥락: 이번 실험의 도구 없는 60분 단일 호출과 AI 준리만가설 증명의 수시간 에이전트 체제는 규모가 다릅니다. P3 결과를 능력 부재로 읽으면 안 됩니다.

인용 금지: 자기 평가를 뺀 난이도 p=0.035는 쓰지 마세요. 평가자가 둘뿐이라 출제 모델과 평가자 효과가 섞여 있습니다. 체커 통과 3건도 모두 한 문제에서 나왔으므로 등급 차이의 근거가 아닙니다.

사용자가 정한 것

  • 모델 역할: 계획은 Fable, 검증은 Opus, 구현은 Sonnet입니다. 다만 Fable 단계가 끝날 때까지 데스크톱 세션은 Opus로 두어 Fable 한도를 아낍니다.
  • 평가 블라인드: 평가자에게 why_important를 숨기고 평가를 시작했습니다.
  • 고컨텍스트 조건: 현재 실험을 끝까지 돌린 뒤, 컨텍스트를 충분히 넣어 소규모로 한 번 더 합니다. 사용자가 논문 컨텍스트를 직접 줄 때 실행합니다. 그 전에는 실행하지 마세요. 기존 4문제와 평가 8건의 처리도 사용자 결정을 기다립니다.
  • 적용하지 않은 변경: 시간 제한 1800초, 예산 1회, 평가 effort 고정입니다. 실험 목적에 맞는 수정만 적용했습니다.
  • 풀이 배정 설계: 평가자 섭외 후로 미뤘습니다.

실행할 때 알아 둘 것

  • 모델 호출: llm.py가 로그인된 Claude CLI를 헤드리스로 부릅니다. 호출당 제한은 3600초이고 도구는 끕니다. 실행 전에 로그인 상태를 확인합니다.
  • 중단 규칙: 연속 5회 실패하면 멈춥니다. 네트워크나 로그아웃이 원인이면 같은 명령을 다시 실행합니다.
  • 종료 코드 3221225794: Windows 로그아웃이나 종료로 CLI가 시작되지 못했다는 뜻입니다. 로그인 후 다시 실행합니다.
  • 알려진 한계: Fable 출력 상한은 64k로 Sonnet과 Opus의 128k보다 낮습니다. effort는 CLI 기본값이고 기록되지 않습니다.
